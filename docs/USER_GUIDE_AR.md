# دليل LANBridge Pro

## الفكرة الأساسية

افتح نفس البرنامج على الجهازين. كل جهاز مسؤول فقط عن إعداداته ومشاركاته المحلية.
ابدأ مهمة النقل من أي طرف بعد السماح بالوصول إلى المشاركة. الإرسال والاستقبال هما اختيار
مصدر ووجهة، ولا تحتاج نسخة Sender منفصلة أو نسخة Receiver.

## اتصال مباشر لأول مرة

1. وصل كابل Ethernet وانتظر ظهور Up وسرعة الكابل في صفحة إعداد الشبكة.
2. اختر كارت Ethernet بدقة، خصوصًا إذا كان لديك Ethernet 2 أو Ethernet 4.
3. على الجهاز الأول: Configure IP ثم Quick PC A. على الثاني: Quick PC B.
4. راجع العنوانين: 192.168.50.1 و192.168.50.2، Prefix 24، وGateway/DNS فارغان.
5. وافق محليًا على المعاينة وUAC والتأكيد المستقل. لا تغير Wi-Fi أو Virtual دون اختيار صريح.
6. إذا كانت الشبكة موثوقة، عيّن Private Profile. أضف قاعدة Allow SMB peer بعنوان الجهاز المقابل.
   القاعدة على Private فقط وعلى المحول المحدد؛ لا حاجة لتعطيل Firewall.

إذا كنت تستخدم Router يعطي عناوين تلقائيًا، ابدأ بـDHCP. لا تستخدم الإعداد السريع إذا كان
192.168.50.0/24 مستخدمًا بالفعل بطريقة تتعارض مع شبكة أخرى. انقطاع الاتصال مؤقتًا عند تغيير IP متوقع.

## مشاركة المصدر أو الوجهة

من الجهاز الذي يملك المجلد افتح File Sharing ثم Create share. أدخل مسار المجلد وحساب Windows
مصرحًا به. Read فقط للمصدر، وWrite فقط إذا كنت تريد أن يستقبل المجلد نسخًا من الطرف الآخر.
لا تستخدم Everyone أو Guest كحل لتجنب كلمة المرور.

إذا كانت أذونات NTFS الحالية كافية، اترك Grant inheritable NTFS permission غير محدد. إذا احتجت
الإضافة فاقرأ المعاينة: الإذن يخص المجلد ومحتوياته الوارثة؛ المجلدات المحمية وDeny لا تُتجاوز.
يمكن إزالة المشاركة التي أنشأها التطبيق والتراجع عن DACL المضاف إذا لم يتغير خارجيًا.

اختيار ملف منفرد في حقل مسار المشاركة يشارك مجلده الحاوي؛ الحساب قد يصل إلى ملفات أخرى داخل
ذلك المجلد حسب NTFS. لن يوهمك البرنامج بأنه أنشأ مشاركة SMB مستقلة لملف واحد.

## تسجيل الدخول مرة واحدة

على الجهاز الذي سيشغّل النسخ، افتح Device Discovery وأدخل اسم الجهاز أو IP وUNC الذي نسخته.
اضغط Connect واستخدم `اسم-الجهاز\اسم-المستخدم` أو `DOMAIN\user`. استخدم كلمة مرور الحساب
الفعلية، وليس PIN الخاص بـWindows Hello. Remember Credentials يحفظها في Windows Credential
Manager للمستخدم الحالي ويعيد استخدامها عند الاتصال من البرنامج.

إذا كان اتصال SMB قائمًا بحساب آخر، قد يظهر الخطأ 1219. راجع اتصالاتك في Windows وأغلق الاتصال
المتعارض بنفسك؛ البرنامج لا يقطع جلسات أخرى تلقائيًا. قيود الدومين أو NTLM/Signing قد تتطلب اسم
الجهاز الصحيح وحساب الدومين أو مساعدة المسؤول. لا تُعطل سياسات الأمان لتجاوز الرسالة.

## النسخ

1. افتح Transfer Center وحدد اتجاه العمل للإرشادات والاستعراض.
2. اختر ملفات متعددة أو مجلدات متعددة. يمكن إدخال مصادر UNC المصرح بها عبر الاستعراض.
3. اختر وجهة محلية أو UNC. لا تضع الوجهة داخل المصدر.
4. Copy folder itself ينشئ مجلدًا باسم المصدر داخل الوجهة؛ Copy contents only ينسخ ما بداخله.
   إذا اخترت أكثر من مجلد بالمحتويات، يمنع التطبيق تعارض ملفين من المصدرين على نفس الوجهة.
5. راجع Preflight preview: لكل مصدر الاسم والنوع والحجم والعدد والمسار، ثم مساحة الوجهة
   والملفات الإضافية والاستثناءات. الملفات الإضافية لا تُحذف؛ الملفات المختلفة قد تُستبدل.
6. Dry run ينشئ تقرير Robocopy بـ/L بدون نسخ ملفاتك. راجعه من Session logs.
7. اضغط Start transfer ووافق على معاينة المهمة. يمكن إظهار/إخفاء المصادر لمتابعة لوحة التقدم.

## إيقاف واستكمال دون إعادة المكتمل

Pause safely يطلب إيقاف محرك النسخ وينتظر خروجه؛ لا تغلق الجهاز قبل ظهور Paused إذا كان
الإغلاق طبيعيًا. Cancel task يحفظ الملفات المكتملة أيضًا. لا يحذف أي منهما المصدر أو النسخ المكتملة.

غدًا افتح الجهازين، تأكد من Ethernet/IP/Mشاركة SMB والاعتماد والمسارات، ثم من Transfer History
اختر المهمة واضغط Resume selected. تتم مقارنة جديدة وتشغيل Robocopy بـ/Z لتخطي المتطابق
واستكمال البيانات المؤهلة. ملف جزئي من برنامج آخر قد يُعاد نسخه. لا تغيّر المصدر بين الجلسات.

إذا اضطررت إلى Force stop أو انقطع التيار، افتح التطبيق مجددًا واختر المهمة Interrupted.
لا يوجد وعد بضمان سلامة بيانات لم تُتحقق بعد انقطاع مفاجئ؛ التحقق النهائي هو المرجع.

## قراءة لوحة النقل

الحجم المطابق والتقدم أثناء النقل ملاحظات تقديرية، وقد لا يتحرك المؤشر أثناء ملف كبير.
السرعة وETA معدلات اكتمال الملفات المطابقة؛ ليست قراءة دقيقة لسرعة بطاقة Ethernet.
Verified files تخص مرحلة التحقق النهائية. Metadata يقارن الحجم والتوقيت؛ SHA-256 يقرأ المحتوى
في النسختين ويستغرق وقتًا إضافيًا. نطاق النسخ يظهر أثناء Robocopy وملف التحقق يظهر أثناء التحقق.

عند فشل ملفات، راجع الرسالة وUnicode log. Retry failed files يعيد الملفات المسجلة فقط بشرط
عدم تغير المصدر. إذا تغيرت الملفات أو أضيفت ملفات جديدة، استخدم Resume لإعادة بناء القائمة.

## إعدادات الأداء

- Threads الافتراضي 8، والمدى 1–128. جرب 4–8 على HDD، و8–16 على SSD وكثرة الملفات الصغيرة
  مع القياس على جهازك؛ عدد أكبر لا يضمن سرعة أعلى.
- حد السرعة صفر يعني بلا حد. يعتمد تفعيله على دعم /IORATE في نسخة Robocopy المحلية.
- FAT/exFAT يحتاج /FFT. لا تنقل ملفًا أكبر من الحد الذي يدعمه FAT32؛ NTFS أفضل لحفظ خصائص NTFS.
- تغيير اللغة يتطلب إعادة فتح التطبيق؛ الثيم يتغير فورًا.

## التشخيص والتراجع

اختر المحول ثم أدخل الجهاز/UNC وشغّل Test connection أو Diagnostics. افحص كل مرحلة منفصلة:
Link، Subnet، Ping، TCP 445، Share access، Credential status وWindows policy. فشل Ping لا
يعني وحده فشل الشبكة. TCP مغلق قد يكون Firewall أو خدمة Server أو مسارًا غير صحيح.

اختبار الكتابة اختياري ومعلن، وينشئ ثم يحذف ملفًا مؤقتًا فقط داخل UNC المحدد.
Export report يحفظ تقرير JSON بلا كلمات مرور؛ لكنه يحتوي أسماء أجهزة ومسارات وعناوين، فراجعه قبل مشاركته.

Restore saved change يعرض التغييرات السابقة: IPv4 وPrivate والمشاركة وقاعدة Firewall. اختر
التغيير الأصلي واقرأ الحالة الحالية والهدف قبل الموافقة. استعادة DHCP تعيد النمط التلقائي وقد
يعطي الخادم عنوانًا مختلفًا. لا تشغّل التراجع أثناء مهمة نشطة.

## النقل النهائي وحذف المصدر

لا حاجة للحذف في النسخ المعتاد. إذا أردت نقلًا نهائيًا، نفّذ أولًا مهمة بخيار SHA-256 حتى تكتمل،
ثم اختر Verified move cleanup من السجل على جهاز المصدر المحلي. ستكتب `DELETE VERIFIED SOURCES`
للتأكيد. يعاد فحص النسختين بمقابض تمنع الكتابة المتزامنة، ثم تُحذف ملفات المصدر واحدة واحدة؛
المجلدات تُترك. الحذف لا يمكن التراجع عنه داخل البرنامج ولا ينفذ تلقائيًا بعد إعادة التشغيل.

## أماكن البيانات وحدود الأداة

السجل وقاعدة المهام: `%LOCALAPPDATA%\LANBridgePro`. التقارير: المجلد `logs` داخله.
لا تضع هذه البيانات داخل مصدر النقل أو وجهته. لا تحذف قاعدة المهام وأنت تريد الاستكمال.

التطبيق لنسخ ملفات المستخدم. لا يرحل Windows أو البرامج المثبتة أو تراخيصها. أغلق البرامج
التي تعدل ملفات المصدر، ولا تغير Junctions أو أسماء المشاركات أو الأقراص أثناء المهمة.
اعتمد البرنامج للعمل الفعلي بعد اختبار النسخة المجمعة على جهازيك وفق دليل القبول المرفق.
